Pages and layouts

Every .html file in pages/ is a route (docs/theming.html is /docs/theming). The engine renders it with Nunjucks before the bundler (Bun's or Vite) sees it, so pages can extend layouts, include partials and call macros. Template names resolve from the project root, then from the htmx-ui package (its components/ and icons/):

{% call code("jinja", title="pages/pricing.html") %} {% raw %}{% extends "layouts/site.html" %} {% from "components/alert/alert.html" import alert %} {% block title %}Pricing · HTMX UI{% endblock %} {% block content %} {% call alert("Launch offer", variant="success") %}20% off the first year.{% endcall %} {% endblock %}{% endraw %} {% endcall %}

JSON data

json(path) reads a JSON file at build time. Keep repeated content (navigation, pricing tiers, team members, release notes) in one file and render it anywhere, with no API and no client-side fetching.

JSON in the browser too

The same files can be imported by client code. Bun and Vite bundle them as plain objects:

{% call code("ts") %} import nav from "./data/docs-nav.json"; console.log(nav.sections.length); {% endcall %}

SVG and icons

svg(path, attrs) inlines an SVG file and sets attributes on its root, and the icon macro builds on it. Inlined SVG inherits colour and costs no extra requests.

{% call code("jinja") %} {% raw %}{{ svg("icons/sun.svg", { class: "size-5 text-primary", "aria-hidden": "true" }) }}{% endraw %} {% endcall %}

Listing files

glob(pattern) returns matching paths across the template roots, sorted. The icon gallery is generated this way, from the package's icons/:

{% call code("jinja") %} {% raw %}{% for path in glob("icons/*.svg") %}…{% endfor %}{% endraw %} {% endcall %}
