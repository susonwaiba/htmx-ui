htmx-ui-plugin-versions keeps the docs of every release online. The version being written renders live at /docs, as usual. Each older one is a frozen build in archive/v<id>/, served at /docs/v<id>/: its pages, scripts and styles exactly as they were released, so later changes to components or layouts can never break them. This website's versions work this way.

Install

{{ cli("add htmx-ui-plugin-versions") }} {% call code("ts", title="htmx-ui.config.ts") %} import { defineConfig } from "htmx-ui-engine"; import docs from "htmx-ui-plugin-docs"; import versions from "htmx-ui-plugin-versions"; export default defineConfig({ plugins: [docs(), versions()], }); {% endcall %}

List the versions. The one being written has no number yet; it is next until it is released:

{% call code("json", title="data/versions.json") %} { "latest": "next", "versions": [{ "id": "next", "label": "next" }] } {% endcall %} {% call code("css", title="styles.css") %} @import "tailwindcss"; @import "htmx-ui/styles.css"; @import "htmx-ui-plugin-versions/styles.css"; {% endcall %} {% call code("ts", title="app.ts") %} import { initVersions } from "htmx-ui-plugin-versions/client"; document.addEventListener("DOMContentLoaded", () => initVersions()); {% endcall %}

It works without the docs plugin, but with it each archived version also keeps its Markdown and its own sitemap, the sitemaps list every version, and search follows the version being read.

Archiving bakes the banner into every frozen page, so it shows without JavaScript. The client only refreshes it, so an old version learns about releases that came after it.

Releasing a version

The plugin adds two CLI commands. Give them scripts, so they run on the runtime you build with:

{% call code("json", title="package.json") %} { "scripts": { "docs:name": "htmx-ui versions:name", "docs:archive": "htmx-ui versions:archive" } } {% endcall %} {{ cli(["run docs:name 1.2.0", "run docs:archive"]) }}
  1. versions:name <x.y.z> numbers next and dates it today. Docs are versioned per minor before 1.0 (0.2.0 becomes 0.2) and per major after (1.2.0 becomes 1); pass 0.2 or 1 to choose yourself. It refuses when the latest version already has a number.
  2. versions:archive builds the site, freezes the latest version's built docs into archive/v<id>/ and opens a new next. Links between docs pages are rewritten into the snapshot, assets move to _assets/, and pages get noindex so old versions don't compete with the latest in search results. --skip-build archives the dist/ you already have.

Commit archive/ and data/versions.json.

{% call alert("Never edit the archive by hand", variant="warning") %} Snapshots are built output. Fix an old version by rebuilding it from its release and archiving it again. Patch releases update the current docs in place rather than getting a version of their own. {% endcall %}

URLs

{{ classes([ ["/docs/...", "The latest version, rendered from pages/docs."], ["/docs/v/...", "An archived version, from archive/v/. Also /docs/v.md and each page's .md with the docs plugin."], ["/docs/versions.json", "The manifest: every version with its path, release date, sitemap and the pages it has."] ], heading="URL") }}

The version in development never reaches a URL: it is always served at /docs, and only archived versions get a /v<id> prefix. Links that must point across versions carry data-version-link, which archiving leaves alone.

Options

{{ classes([ ["prefix", "Route prefix of the docs, the same as the docs plugin's. Default \"/docs\"."], ["file", "The versions file, relative to the project root. The functions behind the commands are exported for release scripts of your own: nameVersion, startNext, archiveDocs, versionId, readVersionsFile and writeVersionsFile. This repository's bun run version:set uses them to name the docs version and set its package versions in one step.
