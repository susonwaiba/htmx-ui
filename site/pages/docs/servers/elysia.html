htmx-ui-engine/elysia exports one function: htmxUi() returns a plugin that answers the paths your own routes don't. This is the adapter to start with: a specific route always beats the plugin's catch-all, so your API and pages can live in either order, and the plugin runs on Bun, Node, Deno and workers.

{{ cli("add elysia") }}

Mount it

{% call code("ts", title="server.ts") %} import { Elysia } from "elysia"; import { htmxUi } from "htmx-ui-engine/elysia"; const app = new Elysia() .get("/api/invoices", () => db.invoices.list()) .post("/api/invoices", ({ body }) => db.invoices.create(body)) .use(htmxUi()) // pages at their routes, assets, public files, 404.html .listen(3000); {% endcall %}

The plugin returns the instance it was given, so .use(htmxUi()).listen(3000) chains as usual. Order doesn't matter: Elysia prefers a specific route over a wildcard, so your own handlers always win over the plugin's catch-all.

Paths that match nothing get the built 404.html, or a plain 404 Not found when you didn't build one.

Options

htmxUi() takes the same options as createSite():

{% call code("ts", title="server.ts") %} import { createSite } from "htmx-ui-engine"; import { htmxUi } from "htmx-ui-engine/elysia"; const site = await createSite({ root: "../marketing" }); new Elysia().use(htmxUi({ site })).listen(3000); {% endcall %} {{ classes([ ["root", "Project root, where htmx-ui.config.ts and pages/ live. Default: process.cwd()."], ["config", "A UserConfig or ResolvedConfig to use instead of reading htmx-ui.config.ts."], ["context", "Values for every render, on top of the config's globals."], ["asset(file, page)", "URL for asset() in site.render() and site.fragment()."], ["site", "A site from createSite(), to render pages and fragments from the same instance."], ["cache", "Keep compiled templates between requests. Default true; false re-reads every template on every render."] ], heading="Option") }}

Fragments

htmx swaps HTML, so return HTML. Elysia sends a Response as-is, and site.fragment() renders a template — with your macros, components and asset() — without a document shell:

{% call code("ts", title="server.ts") %} const site = await createSite(); new Elysia().get("/api/invoices/:id/refund", ({ params }) => { refund(params.id); return new Response(site.fragment("partials/invoice-row.html", { invoice: invoices.get(params.id) }), { headers: { "Content-Type": "text/html; charset=utf-8" }, }); }); {% endcall %}

To render a whole page from request data, use site.render(url, context) and return it — see Server frameworks for the whole picture.

Build first

The plugin serves dist/, not your templates, so render the site before starting the server. While you work on pages, htmx-ui dev is the quicker loop, with hot reload and mock endpoints:

{% call code("bash", title="Terminal") %} htmx-ui build && bun server.ts {% endcall %} {% endblock %}
