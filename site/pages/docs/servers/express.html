htmx-ui-engine/express exports one function: htmxUi() returns Connect middleware that serves the built site. It works with Express 4 and 5, and with anything else on node:http (Connect, a bare http.createServer(app)). On Elysia the same job is one plugin and needs no ordering; this is the adapter for a Node app that already exists.

{{ cli("add express") }}

Mount it

Register it after your own routes: middleware runs in order, so htmx-ui only sees the paths nothing else claimed.

{% call code("ts", title="server.ts") %} import express from "express"; import { htmxUi } from "htmx-ui-engine/express"; const app = express(); app.get("/api/invoices", async (req, res) => { res.json(await db.invoices.list()); }); app.use(htmxUi()); // pages at their routes, assets, public files, 404.html app.listen(3000); {% endcall %}

Paths that match nothing in your routes and nothing in dist/ get the built 404.html, or Express's own 404 when you didn't build one. Errors in your code and in the adapters reach Express's error middleware, so next(error) behaves as you'd expect.

Options

htmxUi() takes the same options as createSite(). Point it at another project, skip the config file, or hand it a site you already created:

{% call code("ts", title="server.ts") %} import { createSite } from "htmx-ui-engine"; import { htmxUi } from "htmx-ui-engine/express"; const site = await createSite({ root: "../marketing" }); app.use("/blog", htmxUi({ site })); // the site under a prefix; assets need hashed URLs for this {% endcall %} {{ classes([ ["root", "Project root, where htmx-ui.config.ts and pages/ live. Default: process.cwd()."], ["config", "A UserConfig or ResolvedConfig to use instead of reading htmx-ui.config.ts."], ["context", "Values for every render, on top of the config's globals."], ["asset(file, page)", "URL for asset() in site.render() and site.fragment()."], ["site", "A site from createSite(), to render pages and fragments from the same instance."], ["cache", "Keep compiled templates between requests. Default true; false re-reads every template on every render."] ], heading="Option") }} {% call alert("Mounting under a prefix", variant="warning") %} A built page loads its assets with URLs relative to its own path, so a site served from /blog looks for them under /blog too. Either mount htmx-ui at the site root, or put a copy of dist/ at that prefix. {% endcall %}

Fragments

htmx swaps HTML, so return HTML. site.fragment() renders a template — with your macros, components and asset() — without a document shell:

{% call code("ts", title="server.ts") %} app.get("/api/invoices/:id/refund", (req, res) => { refund(req.params.id); res.type("html").send(site.fragment("partials/invoice-row.html", { invoice: invoices.get(req.params.id) })); }); {% endcall %}

To render a whole page from request data, use site.render(url, context) and res.send() it — see Server frameworks for the whole picture.

Build first

The adapter serves dist/, not your templates, so render the site before starting the server. While you work on pages, htmx-ui dev is the quicker loop, with hot reload and mock endpoints:

{% call code("bash", title="Terminal") %} htmx-ui build && node server.js {% endcall %} {% endblock %}
