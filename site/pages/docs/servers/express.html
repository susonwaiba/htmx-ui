htmx-ui-engine/express exports htmxUi(), Connect-style middleware that serves the built site. It works with Express 4 and 5, and with anything else built on node:http: Connect, a bare http.createServer(), or NestJS. Use it for a Node app that already exists. For a new one, Elysia or Fastify don't care about registration order.

{{ cli("add htmx-ui-engine express") }}

Mount it last

Middleware runs in order, and htmx-ui answers every request it sees, with a 404 page when nothing matches. Register it after your own routes and middleware, or they will never be reached:

{% call code("ts", title="server.ts") %} import express from "express"; import { htmxUi } from "htmx-ui-engine/express"; const app = express(); app.get("/api/invoices", async (req, res) => { res.json(await db.invoices.list()); }); app.use(htmxUi()); // last: pages, assets, public files, the config's routes, a 404 page app.listen(3000); {% endcall %}

Paths nothing claims get the 404 page: your pages/404.html, or htmx-ui's default. An error thrown while answering goes to next(error), so Express's error middleware handles it as usual.

{% call alert("Mount it at the root", variant="warning") %} The adapter matches a request's full path, prefix included. Mounted with app.use("/blog", htmxUi()), it looks for dist/blog/… and finds nothing. Mount it without a path, and build the site with its pages under pages/blog/ if that is where they belong. {% endcall %}

Fragments and pages

res.type("html").send() sends rendered HTML with the right content type:

{% call code("ts", title="server.ts") %} import express from "express"; import { createSite } from "htmx-ui-engine"; import { htmxUi } from "htmx-ui-engine/express"; const site = await createSite(); const app = express(); app.use(express.urlencoded({ extended: false })); app.post("/api/invoices/:id/refund", (req, res) => { res.type("html").send(site.fragment("partials/invoice-row.html", { invoice: refund(req.params.id) })); }); app.get("/dashboard", (req, res) => { res.type("html").send(site.render("/dashboard", { user: currentUser(req) })); }); app.use(htmxUi({ site })); // the same site: templates compiled once app.listen(3000); {% endcall %}

Body parsers are fine before the adapter: when express.urlencoded() or express.json() has read a request body, the adapter rebuilds it for the config's routes. See Pages & fragments for forms, htmx headers and error fragments.

Options

htmxUi(options) takes the options of createSite(): root, config, context, asset, cache and site. For example, to serve a site from another directory:

{% call code("ts", title="server.ts") %} app.use(htmxUi({ root: "../marketing" })); {% endcall %}

Testing

Listen on port 0 to get a free port, and close the server when the test ends:

{% call code("ts", title="server.test.ts") %} import { expect, test } from "bun:test"; import { app } from "./server"; test("serves the home page", async () => { const server = app.listen(0); await new Promise((resolve) => server.once("listening", resolve)); try { const { port } = server.address() as { port: number }; const res = await fetch(`http://localhost:${port}/`); expect(res.status).toBe(200); } finally { server.close(); } }); {% endcall %}

Build and run

In production the middleware serves dist/, so build first and set NODE_ENV:

{% call code("bash", title="Terminal") %} htmx-ui build && NODE_ENV=production node server.ts {% endcall %}

Node runs server.ts directly from 22.18. See Deploying for what to ship, cache headers and Docker.
