When htmx swaps content it inserts new elements, and a new element starts scrolled to the top. That is right for most content, but not for a sidebar the reader has scrolled to the current page, a log refreshed by polling, or a table re-rendered after a filter. Mark those containers with hx-preserve-scroll and they come back where they were.

Scroll the lists and rows, then re-render them: every element is replaced (the times change), but the marked ones keep their position. For a navigation sidebar, use sidebar-active-scroll instead.

Setup

Register the extension once, after htmx has loaded:

{% call code("ts", title="app.ts") %} import "htmx.org"; import { registerPreserveScroll } from "htmx-ui"; registerPreserveScroll(); // uses window.htmx; or registerPreserveScroll(htmx) {% endcall %}

Like every htmx 4 extension it applies to the whole page once registered; there is no hx-ext. If you restrict extensions with htmx.config.extensions, add preserve-scroll to the list. Registering twice is harmless.

  • The key is what connects the old element with the new one. Use as many containers on a page as you like, each with its own key. An element with no key and no id is ignored.
  • Repeated keys are matched in document order: the first old element with the first new one, and so on. A list of horizontally scrolling rows can share one key, as the two rows in the demo above do.
  • The swap can replace the container itself (outerHTML), its parent, or the whole body in a boosted navigation. It works with OOB swaps and partials too.
  • hx-preserve-scroll="false" opts an element out, for a fragment that should start at the top even though it has the same id.

How it works

  • Before each swap (htmx:before:swap) it records the scroll position of every marked element in the document.
  • New content is scrolled to the recorded position at htmx:before:settle, before the browser paints it, so it never flashes at the top. A last pass at htmx:finally:swap catches content from every task.
  • Elements the swap didn't replace are left alone, so a container the reader scrolls while the request is in flight keeps the reader's position. Morph swaps keep the element and therefore its scroll already.
  • Nothing is stored: positions are kept only for the duration of a swap.

Sidebars: sidebar-active-scroll

Keeping the position is not enough for a navigation sidebar. Open a link in a new tab, or reload, and there is no position to keep: the sidebar starts at the top, and the current page may be far below. A link in the page itself can lead to a page whose sidebar entry is out of view. sidebar-active-scroll handles both:

  • Fresh page load (new tab, reload, a sidebar new to the page): the active item is centred in the sidebar.
  • After a swap: the old position comes back, as with hx-preserve-scroll. If the new active item is then out of view, the sidebar scrolls just enough to show it, with a neighbouring item's height to spare. Clicking a link that is already visible doesn't move anything.
  • A hidden sidebar (an off-canvas panel with display: none) is centred the first time it gets a size.
  • Only the sidebar scrolls; the page never jumps.

  • Put hx-sidebar-active-scroll on the element that scrolls. Its value is the key, with the same rules as hx-preserve-scroll (empty: the id; "false": off).
  • The active item is the first [aria-current="page"] or [data-active] inside, as the Sidebar component marks it. hx-sidebar-active-item="<selector>" picks something else.
  • Use one extension per container. This site's docs sidebar uses sidebar-active-scroll.

API

Exported from htmx-ui:

  • registerPreserveScroll(htmx?): registers the extension as preserve-scroll.
  • snapshotScroll(root?) and restoreScroll(snapshot, root?): the same capture and restore, for DOM you replace yourself.
  • registerSidebarActiveScroll(htmx?): registers sidebar-active-scroll and centres the active item of sidebars already on the page.
  • revealActive(container, mode?): scrolls a container so its active item shows, "nearest" (the default: only if it is out of view) or "center". revealAllActive(root?, mode?) does the same for every [hx-sidebar-active-scroll]; call it after changing aria-current yourself.
