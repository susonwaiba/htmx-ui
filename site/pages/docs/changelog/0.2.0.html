Breaking changes

Two changes need an edit in your config or your command line.

templates is now roots

The two options are one, and roots[0] is the project root, which templates never moved. Rename the key and keep your project directory first unless it already is:

  • Before: defineConfig({ templates: ["."] })
  • After: defineConfig({ roots: ["."] })

A config that still says templates is a TypeScript error, not a silent fallback. ResolvedConfig.templateRoots is gone with it; read ResolvedConfig.roots (the same list, entries as { name?, dir }) and map dir if you needed the bare directories. See Roots.

create-htmx-ui defaults to bun

The scaffolder's --pm default is bun instead of npm. Pass --pm npm (or pnpm, yarn) for the old behaviour. Since bun create htmx-ui already ran Bun, this mostly changes what the scaffolder writes into a new project's package.json scripts and lockfile.

Added

Components

  • Checkbox: a native checkbox styled with the design tokens, in sizes, with disabled, invalid and indeterminate states.
  • Radio group: native radios as cards or inline rows, so a choice is one control that submits with the form.
  • Select: a listbox in a popup opened from a button, styled like an input, searchable and keyboard driven, falling back to the native <select> without JavaScript.
  • Switch: an on/off setting that applies at once, drawn as a sliding track on a real checkbox, so it needs no JavaScript.

Templates and data

  • Named template roots: roots in htmx-ui.config.ts is an ordered list of directories, each optionally named, and the first entry is the project root. A name is the prefix templates reach that directory by, so it can move without a single template changing.
  • Names work everywhere a template name does — extends, include, import, from, json(), svg(), glob() and asset() — because resolution moved into a loader Nunjucks uses for every template load.
  • Deploying templates a server renders at runtime: copy the roots next to dist/ and point roots at the copy.

Engine

  • Serving a site from your own backend: createSite() is the framework-free core of the dev servers, wrapped by htmx-ui-engine/elysia (recommended), htmx-ui-engine/express and htmx-ui-engine/hono. None of them imports its framework.
  • site.render() renders a full page, site.fragment() renders any template as an htmx fragment, and site.handle() answers a request from config routes, the built dist/, the config's fetch, the built 404, then returns null so your framework can answer.
  • render: true in the config checks at startup that the template roots and pages directory arrived, so a packaging mistake fails the boot instead of the first request.
  • A cached runtime renderer: render(path, roots, { cache: true }) with warm() to compile ahead of the first request (createSite() does both), and markup() for a global that returns HTML.
  • debug in the config logs requests, unmatched routes, builds and reloads, per topic.

Package

  • htmx-ui exports queryAll (the helper components use to include the root in their scan) and the Theme type.
  • htmx-ui-engine exports createSite, Site, SiteOptions, normalizeRoots, tryLocate, locate, TemplateRoot, RootSpec, warm, markup and logger.
  • bun run version:set <x.y.z> names the docs version in development, dates it, and sets all three package versions at once.

Changed

  • The dev watcher honours .gitignore and skips node_modules, dist, public and .git whatever the roots say, so a root of . no longer adds a file watcher for every directory in node_modules. The trade-off: a new file under one of those directories shows up on the next refresh rather than immediately.
  • The dev server watches the roots you configured, so a template that moved is still watched.

Fixed

  • assetVer()'s ?ver= can no longer break a build or be dropped by the bundler. Neither Bun nor Vite can resolve an asset URL carrying a query string, so the version is parked in a data-ver attribute before the bundler sees the page and moved onto the finished URL after it.
  • .select no longer restyles the select component's trigger as a native dropdown; the rule is scoped to select.select.
  • A field whose label sits in .field-content — what a switch or a radio group produces — marks an invalid field the same way a top-level label does, instead of losing the danger colour.
